# Платформа 1С под DSH: что оказалось важно

Заметки о том, как ведёт себя платформа, которую запускает `v8-runner`, и что
приходится учитывать в порте и в проектах. Собрано из двух прогонов: Windows 11 +
1С 8.3.27.2325 на Unica 0.15.0-rc.1 и macOS arm64 + 1С 8.3.27.2342 на
0.15.0-rc.5. Здесь только то, что пригодится снова; история отладки — в git.

## Кэш рантайма держать вне рабочего каталога

DSH помечает рабочий каталог низкой целостностью (Low) и ставит на него
capability-ACE. Всё, что создаётся внутри, наследует и метку, и ACE — в том числе
скачанный рантайм. Дальше действует правило Windows: **исполняемый файл с
Low-меткой запускается с Low-токеном**, даже если родитель Medium. Low-процесс не
может писать в объекты Medium, а профиль пользователя — Medium.

Платформе 1С нужно писать в свой профиль (`%LOCALAPPDATA%\1C\1cv8`,
`standalone-server`). Из Low-процесса это запрещено, и симптомы выглядят как три
разных дефекта:

| Что видно | Что на самом деле |
|---|---|
| `ibcmd`: «доступ запрещён» | не может писать в `%LOCALAPPDATA%\1C` |
| `Ошибка указания пути к файлу блокировки … standalone-server/lock.pid` | то же, но сообщение про lock |
| `1cv8 DESIGNER` висит и жжёт процессор | ушёл в цикл вместо ошибки записи |

A/B-проверка на одной машине:

| Где лежит кэш рантайма | Целостность `v8-runner` | `infobase.create` |
|---|---|---|
| `<проект>\.dsh-cache\runtimes` (в рабочем каталоге) | Low (4096) | падает |
| `C:\Users\<вы>\.dsh\port-cache\runtimes` (вне каталога) | Medium (8192) | создаёт базу |

Метка не переезжает вместе с файлом: она наследуется только при создании внутри
помеченного каталога. Поэтому копирование кэша наружу лечит, а копирование внутрь
— ломает.

**Правило.** Кэш рантайма — вне рабочего каталога. Значение по умолчанию
(`$DSH_HOME/unica/runtimes`) как раз снаружи; ловушка возникает, если указать
`--cache-dir` внутрь проекта. Это поведение песочницы DSH, а не дефект порта.

## XML, который платформа считает критичным

Три случая, когда файл проходит валидаторы Unica, а импорт в базу — нет.

### `InternalInfo` в корне конфигурации

```
[ERROR] Файл - …/src/Configuration.xml, узел - Configuration:
        Отсутствует внутренняя информация (узел InternalInfo) для объекта Configuration
```

Пустой `<InternalInfo/>` платформу не устраивает: нужны `<xr:ContainedObject>` с
парами `<xr:ClassId>` / `<xr:ObjectId>`. Руками корень писать не нужно — навык
`cf-init` создаёт его с корректным узлом; альтернатива — снять дамп пустой базы
`DumpConfigToFiles` и взять блок оттуда.

### `LineNumberLength` и режим совместимости

```
[ERROR] Документ.ПоступлениеТоваров.ТабличнаяЧасть.Товары -
        В режиме совместимости 8.3.26 и ниже длина номера строки должна быть равна 5
```

`tabularSection.add` не задаёт `LineNumberLength`. Если корень объявляет
совместимость 8.3.26 или ниже, импорт падает. Лечится либо подъёмом режима до
`Version8_3_27`, либо явным `LineNumberLength = 5`. Кандидат в issue: инструмент
мог бы ставить значение сам.

### Флаги общего модуля

`object.create` для `CommonModule` пишет только `<Server>true</Server>`.
`bsl-analyzer` справедливо ругается:

```
CommonModuleInvalidType: Общий модуль должен быть одного из типов:
Server, ServerCall, Client, ClientServer
```

Стандарт требует набора `Server + ExternalConnection + Client (обычное
приложение)` для серверного модуля. Платформа такой модуль молча импортирует, так
что ловится это только диагностикой. Исправляется тем же инструментом:

```json
{ "at": "main:CommonModule.Имя", "ops": [
  { "op": "props.set", "args": { "values": {
      "Server": true, "ExternalConnection": true, "ClientOrdinaryApplication": true } } } ] }
```

## Лицензия 1С

Признак, который легко принять за дефект порта: `push` и `download` отвечают
`credentials_rejected` («the designer agent rejected the infobase user … user ''»),
хотя база файловая и пользователей в ней нет. Платформа пишет настоящую причину в
`/Out`-лог:

```
Запуск системы выполнен без использования аппаратной лицензии (ключа защиты).
```

Проверить одной командой:

```sh
/opt/1cv8/8.3.27.2342/1cv8 DESIGNER /F<путь к базе> /CheckConfig /Out/tmp/1c.txt
cat /tmp/1c.txt
```

После активации лицензии те же `push` и `download` проходят без изменений в
проекте.

## Vanessa Automation

Для сценарных тестов нужен **весь комплект** Vanessa, а не только `.epf`: без
соседних `locales/`, `lib/` и `features/` она падает на открытии формы
(«Каталог не обнаружен …/locales/Steps.epf»).

Сценарии не поедут, пока в `VAParams` нет профиля клиента тестирования и флага
запуска. Рабочий `va-params.json`:

```json
{
  "КаталогФич": "<проект>/features",
  "ПутьКVanessaAutomation": "<проект>/tools/VanessaAutomation.epf",
  "КлиентыТестирования": [{
    "Имя": "Тестовый",
    "ПутьКИнфобазе": "/F<проект>/build/ib",
    "ТипКлиента": "Тонкий",
    "ИмяКомпьютера": "localhost",
    "ПортЗапускаТестКлиента": "1538"
  }],
  "ВыполнитьСценарии": true,
  "ЗавершитьРаботуСистемы": "Истина",
  "ВыгружатьСтатусВыполненияСценариевВФайл": "Истина",
  "ПутьКФайлуДляВыгрузкиСтатусаВыполненияСценариев": "<проект>/build/va-status.json",
  "ИмяФайлаЛогВыполненияСценариев": "<проект>/build/va-run.log"
}
```

Запуск через `unica.run`:

```json
{ "op": "launch", "args": {
    "clientMode": "thin",
    "execute": "tools/VanessaAutomation.epf",
    "applicationParameter": "StartFeaturePlayer;VAParams=<проект>/va-params.json",
    "waitForExit": true,
    "waitTimeoutMs": 180000
} }
```

Признак успеха — `exit code 0`, `build/va-status.json` = `0`, выполненный сценарий
в `build/va-run.log`.

Фича должна использовать только встроенные шаги Vanessa: собственные
формулировки без `step_definitions/*.bsl` дают `Pending: Не найдена процедура или
функция для выполнения шага`.

## Известные пробелы

- **`upload` недоступен** в адаптере `v8-runner` 0.15 (`unsupported_operation`):
  готовый `.cf`/`.cfe` в базу не залить, только `push` исходников.
- **Запуск тестов YaXUnit** на поверхности Unica не опубликован: авторинг тестов
  и поиск по ним есть, запуск — отдельный шаг вне инструментов.
- **Первый платформенный вызов** заметно дольше остальных: холодный `ibcmd`
  поднимает служебные каталоги. Это не зависание — `unica.run` возвращает
  `taskId`, дождитесь `unica.task.result`.
