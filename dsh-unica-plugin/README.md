# dsh-plugin-unica — Unica для DeepSeek Harness

Порт [Unica](https://github.com/IngvarConsulting/unica) для DSH: навыки разработки
на 1С:Предприятии и нативный мост к `unica` как родные инструменты DSH.

Мост берёт рабочий каталог из каждой сессии DSH и держит пул процессов unica по
каталогам — один профиль обслуживает любое число проектов.

- **Unica 0.15.0-rc.5**, ревизия порта 6
- **11 инструментов** (в 0.12 их было 74)
- **50 навыков**, **46 файлов справочников**
- Платформы: **Windows x64**, **Linux x64**, **macOS arm64**

## Установка

**Одной командой** — скачает релизный архив, сверит SHA-256, распакует плагин в
постоянный каталог и передаст управление установщику:

```sh
# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/malinovme/dsh-unica/main/install.sh | sh
```

```powershell
# Windows
irm https://raw.githubusercontent.com/malinovme/dsh-unica/main/install.ps1 | iex
```

Чтобы закрепить версию, передайте её именно процессу `sh` (на Windows — параметр
`-Version` скрипту):

```sh
curl -fsSL https://raw.githubusercontent.com/malinovme/dsh-unica/main/install.sh | UNICA_VERSION=v0.15.0.6 sh
```

Скрипт сам выбирает профиль (`desktop`, если он есть, иначе `web`) и после
установки **поднимает unica**, чтобы проверка была не про файлы, а про
результат. Если каталог кэша отказывает демону сервера, он переезжает
автоматически.

Переопределяется переменными (`UNICA_VERSION`, `UNICA_PROFILE`,
`UNICA_DSH_HOME`, `UNICA_INSTALL_DIR`, `UNICA_VERIFY=0`) или параметрами
PowerShell (`-Version`, `-Profile`, `-DshHome`, `-NoVerify`).

**Вручную**, из распакованного архива — он раскрывается **без обёртки**, то есть
его содержимое и есть каталог плагина:

```powershell
node install.mjs                      # агент-пресет для Web GUI (по умолчанию)
node install.mjs --verify             # плюс самопроверка моста
node install.mjs --target both        # ещё и патч профиля headless
node install.mjs --dry-run            # показать план, ничего не писать
```

`--verify` стоит того: он единственный отвечает на вопрос «режим заработает?».
Профиль может быть собран идеально и всё равно содержать строку, плагин которой
не стартует. Ожидаемый результат:

```
native check  : ok      serverInfo unica 0.15.0-rc.5, 11 tools in 377 ms, workspace /…
```

Первый запуск скачивает ядро (~15 МБ) — на медленной сети это минуты, и
`--verify` даёт на холодный кэш отдельный бюджет времени.

Затем **перезапустите сервер DSH** и **начните новую сессию** с пресетом
**«Unica 1C»**.

### Какой профиль получит установку

Развилка одна: **если стоят и DSH Desktop, и Web GUI, скрипт выберет `desktop`** —
по наличию `$DSH_HOME/profiles/desktop`. У кого Desktop нет, тот получит `web`.
`install.mjs`, запущенный руками, по умолчанию пишет в `web`.

| Что у вас работает | Чем ставить |
|---|---|
| Только Web GUI | `curl … \| sh` без переменных |
| Только DSH Desktop | `curl … \| sh` без переменных |
| **Оба** | двумя вызовами: `UNICA_PROFILE=web` и `UNICA_PROFILE=desktop` |
| Web GUI и headless/TUI | `node install.mjs --target both --verify` |

Строки между профилями дублировать не нужно: сессии обоих приложений собираются
из пресета, а `unica-native` и `skill-filesystem-unica` для профилей без пресетов
живут в `headless`.

## Как это устроено

### Слой запуска

В 0.12 порт возил с собой три бинарника `unica-bootstrap`. В 0.13 апстрим их не
поставляет: релиз публикует **архив рантайма под каждую цель** плюс дескриптор с
SHA-256 и списком файлов. Поэтому лаунчер свой, на Node (`bootstrap/launch.mjs`):

1. выбирает цель по платформе и читает `runtime-manifest.json`;
2. если кэш уже готов — запускает сервер, ничего не трогая;
3. иначе качает архив, считает SHA-256 **по потоку**, сверяет, распаковывает во
   временный каталог, проверяет хеши файлов и только потом **переименовывает**
   каталог в место — так полузаписанный кэш никогда не выглядит готовым;
4. пишет `.ready.json` и передаёт управление серверу с унаследованным stdio.

Ничего исполняемого порт не поставляет — отсюда и отсутствие бинарников в
репозитории.

### Кэш и демон

Unica 0.13 держит **постоянный пользовательский демон**, и сервер открывает его
корень состояния при старте. По умолчанию порт кладёт всё в
`$DSH_HOME/unica/{runtimes,provider-state}`.

На Windows этого иногда недостаточно: `$DSH_HOME` под профилем пользователя может
нести маску каталога, которая отказывает демону, и тогда сервер падает с
`open daemon provider state root: Отказано в доступе. (os error 5)` за доли
секунды. Симптом виден через три шага, как «пресет не загрузился». Лечится
переносом:

```powershell
node install.mjs --target preset --profile desktop --cache-dir D:\unica-cache
```

`--verify` делает это сам, если видит отказ.

### Движки по требованию

Ядро маленькое, а `bsl-analyzer`, `rlm-bsl-index`, `rlm-bsl-mcp` и `v8-runner`
скачиваются при первом обращении к соответствующей возможности. Значит, первый
такой вызов требует сети и заметно дольше остальных — это записано и в правила
сессии.

### Как проверить, что режим работает

Коротко — `node host/selftest.js --cwd <проект>` (поднимает unica и читает
`unica.view {}`), подробнее — [docs/native-verification.md](../docs/native-verification.md):
только то, что обязано пройти при правильной установке. Платформенные операции,
формы, СКД и расширения — в
[docs/platform-verification.md](../docs/platform-verification.md).

### Пространство имён инструментов

Unica называет инструменты с точками (`unica.view`, `unica.apply`). Прежняя
MCP-строка публиковала их как `mcp__<server>__<имя>`; мост сохраняет эти имена,
а если нормализация что-то потеряла — дописывает 12 hex-символов SHA-256 от
`"<server>\0<raw name>"`:

```
unica.view  ->  mcp__unica__unica_view_6f3a42290cc8
```

Формула воспроизведена в `host/lib/naming.js` и проверяется тестом на любой
машине. Соответствие лежит в `tool-map.json` (11 записей), а
`tools/build-skills.mjs` переписывает по нему текст навыков при каждой
регенерации: 679 ссылок в 52 файлах. Если навык упоминает имя, которого нет в
карте, генерация падает — это лучше, чем инструкция, которую модель не сможет
выполнить.

## Что изменилось при переходе на 0.13 и что дала 0.15

Апстрим переработал поверхность в 0.13, поэтому порт переписан, а не обновлён.
От 0.15.0-rc.1 до 0.15.0-rc.5 поверхность не менялась — те же 11 инструментов;
набор навыков сократился с 55 до 50 (DCS, MXL, роль- и подсистема-компиляция
ушли в нативные операции апстрима, добавились `localization` и `unica-dev`).

| | 0.12.3 (порт был) | 0.13.0 | 0.15.0-rc.5 (сейчас) |
|---|---|---|---|
| Инструментов | 74 | **11** | **11** |
| Навыков | 76 | **55** | **50** |
| Рантайм | bootstrap + 302 МБ | **`unica`, 10.4 МБ**, движки по требованию | **`unica`, 15.3 МБ**, движки по требованию |
| `v8-runner` | — | 0.14.0 | **0.15.3** |
| Провайдер `kb-1ci` в `docs` | — | есть, падает по таймауту | **убран** |
| Библиотеки в репозитории | 3 бинарника | **нет** | **нет** |
| Манифест | schema v1, 50 КБ | schema v2, дескриптор на цель | schema v2, секция `artifacts` |

**Четыре правки порта удалены, а не переведены.** Они описывали `role.edit`,
`meta.add`, `role.compile` и `v8-runner`; ни этих инструментов, ни навыка
`v8-runner` больше нет. Новый контракт отвечает на большую часть того, о чём они
предупреждали: `apply` сначала строит план и только потом пишет. Правила в
персоне теперь описывают 0.13:

- адресация через `at` (`<sourceSet>:<Kind>[.<Name>...]`), аргумента `cwd` нет;
- `unica.apply` планирует: вызов с `at` и `ops` возвращает `data.executionToken` и
  ничего не меняет; повторный вызов только с токеном исполняет сохранённый план;
- `unica.check` запускает все валидаторы вида узла — отдельных `*.validate` нет;
- контракты аргументов не приходят по проводу: что узел принимает, видно в его
  `can`-словаре (`unica.view` с `filter: {sections: ["can"]}`), а отказ называет
  поле в `diagnostics[].message`; `unica.docs` ищет документацию 1С, не контракты;
- движки скачиваются при первом использовании.

Новая правка должна опираться на наблюдение в поле против 0.13; выдумывать её
нельзя — она попадёт модели как факт.

## Перенос на другую машину

```powershell
# проще всего — скриптом на целевой машине: каталог копировать не нужно
curl -fsSL https://raw.githubusercontent.com/malinovme/dsh-unica/main/install.sh | sh
```

Либо скопировать каталог и поставить из него: `node install.mjs --target both
--verify`. Абсолютные пути в файлах плагина не хранятся — их подставляет
`install.mjs` в момент установки.

## Ограничения

- **macOS arm64 only.** Бинарников под Intel-маки апстрим не поставляет.
- **Нужен Node.js** — он и так требуется DSH; порт своих бинарников не возит.
- **Сеть при первом запуске** — ядро (~15 МБ) и движки по требованию.
- **Права шире песочницы** для реальной работы: правка исходников 1С вне рабочего
  каталога требует `danger-full-access`.
- **Справочники апстрима** всё ещё упоминают десять имён инструментов 0.12 в
  спеках форм и DSL. Это документация, а не инструкции; переписывать её означало
  бы выдумать соответствие и выдать догадку за текст апстрима.

## Лицензии

Навыки и справочники — из Unica (см. `LICENSE`, `ATTRIBUTIONS.md`). Порт больше
не распространяет сторонние бинарники: рантайм и движки скачивает лаунчер на
машине пользователя, со своим лицензионным статусом у каждого.
