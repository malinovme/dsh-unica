# dsh-plugin-unica

Порт публичного плагина [Unica](https://github.com/IngvarConsulting/unica) (Codex /
Claude Code) на **DeepSeek Harness**: 76 навыков по разработке на
1С:Предприятии, справочный корпус из 48 документов и MCP-сервер `unica` с 74
инструментами.

Собственный код unica не менялся. Порт — это интеграционный слой: каталог
навыков с переписанным пространством имён инструментов, справочники, строка
MCP-клиента и установщик, который раскладывает всё по `$DSH_HOME`.

## Установка

```powershell
cd dsh-unica-plugin
node install.mjs                      # агент-пресет для Web GUI (по умолчанию)
node install.mjs --target both        # ещё и патч профиля headless/TUI
node install.mjs --dry-run            # показать план, ничего не писать
node install.mjs --dsh-home D:\other-dsh
```

Затем **перезапустите сервер DSH** и **начните новую сессию**, выбрав пресет
**«Unica 1C»**. Оба шага обязательны: состав сессии фиксируется при её создании,
а реестр пресетов собирается при загрузке профиля — в уже идущем процессе новой
строки ещё нет.

Проверить установку, не заходя в GUI:

```powershell
node tools/verify-install.mjs "$env:USERPROFILE\.dsh" web
```

**Требуется DSH 0.2.0 или новее** — в 0.1.x пресеты устроены иначе (см. ниже).

## Установка в DSH Desktop (macOS / Windows)

DSH Desktop поднимает **свой профиль**, а не `web`. Имя профиля — `desktop`, и он
собирается из того же бандла `dsh-web-app`, то есть агент-плоскость в нём
пресетная, как в Web GUI. Проверить имя на своей машине:

```sh
ls ~/.dsh/profiles          # macOS / Linux
dir %USERPROFILE%\.dsh\profiles   # Windows
```

Дальше установка отличается только флагом `--profile`:

```sh
cd dsh-unica-plugin
node install.mjs --target preset --profile desktop
```

`--profile desktop` здесь обязателен: по умолчанию цель `preset` пишет в профиль
`web`, а `both` добавляет ещё и патч профиля `headless`. Для Desktop нужен
именно `preset` — строки MCP и каталога навыков ставятся внутрь композиции
пресета, а не в сам профиль.

**Никаких переменных окружения задавать не нужно.** Desktop держит харнесс не в
`node_modules`, а внутри своего бандла — `<установка>/resources/app.asar`, где
пакеты лежат в `dsh/node_modules/@deepseek-ai/`. Установщик и проверки читают
шаблон пресета, `js-yaml` и схему объявления прямо оттуда, поэтому установка в
Desktop работает так же, как в Web GUI. Если харнесс лежит нестандартно,
`DSH_INSTALL_ROOT` принимает и каталог с `node_modules`, и путь к `app.asar`,
и каталог `resources`.

### macOS: два шага, без которых не заработает

1. **Карантин.** Скачанный браузером архив помечается `com.apple.quarantine`, и
   Gatekeeper не даст запустить `unica-bootstrap` — это неподписанный сторонний
   бинарник. Снять метку с каталога плагина:

   ```sh
   xattr -dr com.apple.quarantine ~/Downloads/dsh-unica
   ```

   Если плагин получен через `git clone`, карантина нет и шаг не нужен.

2. **Право на запуск.** В git для `bootstrap/launch.sh` и
   `bootstrap/bin/darwin-arm64/unica-bootstrap` записан режим `100755`, поэтому
   клон их получает исполняемыми. А вот распакованный архив — нет: он собран под
   Windows, где такого режима не существует. Одна команда:

   ```sh
   chmod +x ~/Downloads/dsh-unica/dsh-unica-plugin/bootstrap/launch.sh \
            ~/Downloads/dsh-unica/dsh-unica-plugin/bootstrap/bin/darwin-arm64/unica-bootstrap
   ```

### Проверка и запуск

```sh
node tools/verify-install.mjs "$HOME/.dsh" desktop
```

Проверка собирает профиль **загрузчиком самого Desktop** — модули для этого
копируются из его бандла во временный каталог, потому что обычный Node не умеет
импортировать из `app.asar`. В выводе будет видно, какой харнесс использован:

```
harness     : (bundled in the Desktop app)
desktop     : …\resources\app.asar
composed    : 184 top-level entries, 323 rows in total
  ok      `preset-unica-1c` is in the composed tree
```

Затем **выйдите из DSH Desktop и запустите его снова** (реестр пресетов
собирается при загрузке профиля) и начните **новую сессию** с пресетом
**«Unica 1C»**.

### Что ещё стоит знать про macOS

- Нужен только `darwin-arm64`. Бинарников под Intel-маки апстрим не поставляет,
  поэтому на Intel-ноутбуке порт не заведётся — установщик скажет об этом прямо.
- `launch.sh` запускается через `sh`, поэтому способ запуска на macOS — `shell`,
  а не прямой exec, как на Windows. Скрипт апстримный, порт его не менял.
- Сеть нужна один раз: bootstrap скачивает ядро unica (~100 МБ) с GitHub при
  первом запуске MCP-сервера и дальше работает офлайн.
- Для реальной работы нужны права шире песочницы: правка исходников 1С вне
  рабочего каталога и запись в кэш unica требуют `danger-full-access`.

### Что ещё стоит знать про Windows

- Ни карантина, ни `chmod` здесь нет: способ запуска — прямой вызов
  `bootstrap\bin\win-x64\unica-bootstrap.exe`, без шелла и без Git.
- Всё, что нужно, — команды установки выше и перезапуск приложения. Каталог
  установки Desktop (`%LOCALAPPDATA%\Programs\DeepSeek Harness`) ищется
  автоматически; если он нестандартный, укажите `DSH_INSTALL_ROOT`.

## Перенос на другую машину

Плагин переносится как обычный каталог. Абсолютные пути не хранятся в файлах
плагина: их подставляет `install.mjs` в момент установки, поэтому копия на
другой машине просто переустанавливается.

```powershell
# 1. скопировать каталог (или распаковать архив) на целевую машину
# 2. поставить — установщик сам определит ОС и подберёт способ запуска
node install.mjs --target both
```

Три сценария:

| Куда | Что делать |
|---|---|
| Другая машина, тот же `$DSH_HOME` | Скопировать каталог и выполнить `node install.mjs --target both` |
| Другая машина, другой `$DSH_HOME` | То же; либо `node install.mjs --dsh-home D:\other --target both` |
| **DSH Desktop** (macOS / Windows) | `node install.mjs --target preset --profile desktop`; на macOS перед этим — `xattr` и `chmod` (см. «Установка в DSH Desktop») |
| macOS / Linux | То же — `install.mjs` определяет ОС через `process.platform` |

**Сборка архива для передачи:**

```powershell
node package.mjs                                    # 0.4 МБ, без бинарников bootstrap
node package.mjs --include-bootstrap                # 4.4 МБ, самодостаточный
node package.mjs --out D:\dist\unica.tar.gz
```

Рядом кладётся `<архив>.sha256.json` с контрольной суммой, списком файлов и
числом файлов. Slim-сборка **намеренно** исключает `bootstrap/bin/`: это
сторонние прекомпилированные бинарники со своими лицензиями, и конкретной
машине нужен только её собственный. Получателю нужно либо взять их из пакета
апстрима, либо использовать `--include-bootstrap`. Установка из slim-сборки
падает сразу и называет недостающий путь — молчаливо нерабочего плагина не
получится.

### Как выбирается способ запуска

`install.mjs` смотрит на `process.platform` (переопределяется флагом
`--platform`):

- **Windows** — прямой запуск `bootstrap/bin/win-x64/unica-bootstrap.exe`. Без
  шелла и без Git: это наименее хрупкий вариант.
- **macOS / Linux** — `sh bootstrap/launch.sh <plugin-root>`. Скрипт апстрима
  сам разбирает ОС и архитектуру, поэтому порт не дублирует его таблицу целей.
  Git здесь тоже не нужен: Git требуется только маркетплейсному `.mcp.json`,
  который идёт через command-scoped Git-алиас ради восстановления корня
  плагина. DSH передаёт корень обычным аргументом, так что алиас не нужен.

Поддерживаются `darwin-arm64`, `linux-x64`, `win-x64` — ровно те цели, для
которых unica поставляет bootstrap. Любая другая платформа даёт явную ошибку.

Известное ограничение: ветка `launch.sh` **не проверена натурно**, потому что
Git-bash в песочнице этой машины не запускается (`CreateFileMapping ... Win32
error 5` — блокировка именованных каналов). Генерация конфига для неё
проверена: `--dump-config` разбирает получаемый YAML без ошибок, и весь CI-прогон
проходит с `CI_PLATFORM=linux node tools/ci-dryrun.mjs`. Скрипт при этом
апстримный и портом не изменялся.

## Если пресета нет в списке

Симптом: установщик отработал без ошибок, но после перезапуска DSH в списке
режимов нет «Unica 1C». Причины по частоте:

| Что проверить | Как |
|---|---|
| Сервер DSH перезапущен | реестр пресетов собирается при загрузке профиля, а не на лету |
| Пресет вообще попал в профиль | `node tools/verify-install.mjs "$env:USERPROFILE\.dsh" web` — покажет собранное дерево |
| Строка объявлена с `insert:` | в `profiles/web/cordis.patch.yml` строка `- id: preset-unica-1c` должна быть **вложена** в `- insert:` |
| Версия DSH | нужна 0.2.0+; на 0.1.x пресеты устроены иначе |
| Что сказал сам DSH | `dsh --profile web --dump-config`: дерево в stdout, причина отказа — в stderr |

Отдельно стоит знать про поведение, из-за которого этот раздел появился:
объявление без `insert:` **не даёт ошибки в GUI** — только строку
`patch: entry "preset-unica-1c" not found` в stderr и профиль, собранный без
пресета. Поэтому `verify-install.mjs` проверяет собранное дерево, а не файл.

## Правки порта поверх апстрима

Копия навыков больше не байтовая: в четырёх навыках есть раздел «Правка порта».
Он фиксирует случаи, когда поведение инструмента расходится с тем, что обещает
собственная документация unica:

| Навык | Записанное расхождение |
|---|---|
| `v8-runner` | Сбой чтения файла-списка при частичной загрузке (UTF-8 с BOM, кириллица в путях) **не** вызывает автоматический полный повтор: тот срабатывает только на структурированный результат после кода возврата `4`. Повторять сразу с `fullRebuild: true` |
| `register-design` | `meta.add`/`meta.edit` не принимают `RegisterType` — генератор пишет `Balance`, тогда как спецификация называет `Balances`/`Turnovers`; для `Turnovers` нужна правка XML |
| `role-compile` | Обновить существующую роль инструментами нельзя: `role.edit` не принимает `cwd` и падает с `source_set_unknown`, а `role.compile` пропускает существующую роль даже с `Force` |
| `code-patch` | Вызов без `cwd` ищет источник в домашнем каталоге и падает с `SourceSetNotFound` |

Три правила из четырёх продублированы в персоне пресета, поэтому действуют в
каждой сессии, а не только при загруженном навыке. Исходники — таблица
`PORT_NOTES` в `tools/build-skills.mjs`; она применяется до переименования
инструментов и падает с явной ошибкой, если якорь пропал.

## Как это устроено

### Навыки

76 каталогов `skills/unica-<skill>/SKILL.md` — копия апстрима, кроме двух
правок: **пространства имён инструментов** (ниже) и четырёх разделов «Правка
порта» (см. выше).

Навыки unica адресуют инструменты как `unica.<домен>.<действие>`. DSH отдаёт
MCP-инструменты модели под именем `mcp__<serverName>__<raw name>`, где символы
вне `[A-Za-z0-9_-]` заменяются на `_`, а при потере информации (точка —
недопустимый символ) дописывается 12 hex-символов SHA-256 от идентификатора:

```
unica.cf.init            -> mcp__unica__unica_cf_init_60b2c7880b08
unica.cfe.patch_method   -> mcp__unica__unica_cfe_patch_method_bd57b4c031f1
unica.runtime.job.cancel -> mcp__unica__unica_runtime_job_cancel_8b0b07231c28
```

Полная карта — `tool-map.json` (74 записи). Переписано 1011 ссылок в 81 файле;
это делает `tools/build-skills.mjs`.

Имена вида `unica.runtime.job.*` в прозе навыков (`«Не используй
unica.runtime.job.* как fallback»`) намеренно **не** переписаны — это описание
семейства, а не вызов, и в тексте остаётся читаемым. Так же намеренно не
тронуты имена операций внутри JSON-payload'ов (`role.create`, `code.replace`,
`xs:decimal`): это не имена инструментов, а значения аргументов.

### Справочники

`references/` (48 документов, ~920 КБ) копируется в корень плагина. 26 навыков
ссылаются на него как `../../references/...`; от файла навыка
`<plugin>/skills/unica-<skill>/SKILL.md` этот путь разрешается в
`<plugin>/references/` — ровно туда, куда корпус и положен.

Глубина вложенности здесь принципиальна: каталог порта называется
`unica-<skill>`, но лежит на том же уровне, что и апстримный `<skill>`, поэтому
исходные относительные пути продолжают работать **без перепривязки**. Любая
попытка «починить» их на `../references/` ломает все 61 ссылку.

### MCP-сервер

```
unica-bootstrap.exe run --plugin-root <PLUGIN_ROOT>
```

`command` — это **bootstrap**, а не ядро. Bootstrap сверяет закреплённый
`runtime-manifest.json` (SHA-256 архива и каждого файла), атомарно публикует
ядро в кэш и только потом запускает единственный stdio-процесс `unica`.
Запуск `unica.exe` из кэша напрямую прошёл бы мимо этой проверки.

Оба записываемых каталога пинованы явно:

- `UNICA_RUNTIME_CACHE_DIR` → `$DSH_HOME/unica/runtimes`
- `UNICA_PROVIDER_STATE_DIR` → `$DSH_HOME/unica/provider-state`

Без второго bootstrap ушёл бы по цепочке фолбэков к `CODEX_HOME` и дальше к
`~/.codex/unica/provider-state`, то есть порт писал бы состояние внутрь
установки Codex на той же машине. Значение, содержащее `${`, bootstrap
отбрасывает, поэтому здесь всегда абсолютный путь.

### Агент-пресет (для Web GUI)

Web-сессии DSH собираются из агент-пресета, а штатный пресет `standard`
монтирует собственную строку `skill-filesystem` и **отключает** хостовую. Плюс
у пресетов нет наследования «standard + одна правка», поэтому установщик
копирует композицию `standard` и дописывает в неё две строки — ровно так же,
как это делают поставляемые пресеты `cordis` и `ptc`.

Сам пресет — это **строка плагина**, добавленная в `cordis.patch.yml` профиля
`web` через `- insert:`:

```yaml
- insert:
    - id: preset-unica-1c
      name: '@deepseek-ai/dsh-agent-preset'
      config:
        id: unica-1c
        name: Unica 1C
        order: 50
        plugins: [ ... композиция ... ]
```

**`- insert:` здесь обязателен, и это неочевидно.** Запись верхнего уровня
`- id: <x>` в патче не объявляет новую строку, а **адресует** строку нижнего
слоя, чтобы переопределить её конфиг. Объявление без `insert:` DSH молча
отбрасывает: профиль собирается без пресета, а в stderr появляется только
`patch: entry "preset-unica-1c" not found`. Установка при этом выглядит
успешной, и режим просто не появляется в списке.

Так устроен DSH 0.2.0. В 0.1.x пресеты обнаруживались **сканированием
каталогов**: пакет `@deepseek-ai/dsh-agent-presets` читал
`$DSH_HOME/.agent-presets/<id>/preset.yml` и `agent.cordis.yml`. В 0.2.0 этот
пакет удалён, а реестр пресетов «не сканирует каталоги и не принимает пути к
пресетам» — поэтому установка, оставшаяся в старом каталоге, просто исчезает из
списка режимов без единой ошибки. Установщик в этот каталог больше не пишет.

### Патч профиля (headless / TUI / SDK / ACP)

Для этих профилей пресеты не участвуют, достаточно `cordis.patch.yml`. Цель
`--target profile` дописывает в `$DSH_HOME/profiles/<profile>/` две строки
(`mcp-unica` и `skill-filesystem-unica`) — тем же `- insert:`. Строки, которыми
владеет установщик, удаляются из патча перед записью (и как запись верхнего
уровня, и как вложенная — смотря что оставила прежняя версия), поэтому повторный
запуск не накапливает дубли и не трогает чужие записи. Целевой профиль по
умолчанию — `headless`, у цели `preset` — `web`; переопределяется флагом
`--profile`.

### Как убедиться, что установка видна DSH

```sh
node tools/verify-install.mjs "$DSH_HOME" web        # или headless
```

Инструмент собирает профиль **загрузчиком самого DSH** и проверяет, что нужные
строки попали в результат. Это единственная проверка, которая ловит описанную
выше ошибку с `insert:`: текстовые проверки её пропускают, потому что файл
разбирается как YAML и выглядит правильным.

## Требования

- **DSH 0.2.0 или новее.** В 0.1.x пресеты обнаруживались сканированием
  `$DSH_HOME/.agent-presets`, и установщик писал файлы туда; в 0.2.0 этот
  механизм удалён, поэтому на старом DSH пресета в списке не появится.
  `tools/validate-preset.mjs` говорит об этом прямо, а не падает невнятно.
- **1С:Предприятие** нужна только операциям, которые действительно запускают
  платформу: `unica.build.*`, `unica.runtime.*`. Чтение метаданных, разбор
  форм, СКД и MXL, поиск и диагностика BSL работают без неё.
- **Windows x64, macOS и Linux**: способ запуска подбирается автоматически
  (см. «Как выбирается способ запуска»). Для macOS поддерживается только
  `arm64` — отдельных бинарников под Intel-маки unica не поставляет.
- **Сеть при первом запуске**: bootstrap скачивает ядро (~100 МБ) с GitHub.
  Дальше всё офлайн. Для закрытого контура кэш нужно наполнить на машине с
  доступом и перенести каталог `$DSH_HOME/unica/runtimes` целиком: отдельной
  команды предзагрузки в этой версии bootstrap нет — он знает только `run` и
  `verify`.
- **Права**: `workspace-write` не даст писать в исходники 1С вне текущего
  workspace, а также в пользовательский кэш unica. Для реальной работы
  запускайте DSH в режиме с более широкими правами.

## Известные ограничения

- **`startup_timeout_sec` DSH не поддерживает.** Апстрим объявляет его в
  `.mcp.json`, чтобы уложить первую закачку ядра в бюджет старта; DSH использует
  60-секундный дефолт MCP SDK на `initialize` и `tools/list`. Холодный кэш в
  это окно, скорее всего, не уложится — либо прогрейте кэш, либо оставьте
  `reconnect` включённым: после появления ядра сервер поднимется сам.
- **74 инструмента в каждом запросе.** Определения инструментов добавляют
  токены к каждому запросу модели. Если это дорого — сузьте набор до нужных
  доменов (`meta.*`, `form.*`, `code.*`) отдельным сервером.
- **`allowed-tools` из навыков не действует.** DSH не читает этот ключ
  frontmatter (неизвестные ключи игнорируются молча), поэтому ограничения
  набора инструментов, объявленные в навыках, не применяются.
- **`agents/openai.yaml`** из навыков `epf-init` и `erf-init` удалены. Это
  инертная UI-метаданные Codex (`interface.display_name` / `short_description`
  / `default_prompt`), их не читает ни один бинарник unica.
- **`epf-bsp-add-command`** — единственный навык без ссылок на MCP: он
  инструктирует работать напрямую через `Read`/`Edit`/`Glob`/`Grep`.

## Лицензии

Собственный код Unica — **LGPL-3.0-or-later** (`LICENSE`). Встроенные
инструменты сохраняют собственные лицензии — см. `ATTRIBUTIONS.md`:
`v8-runner` (**AGPL-3.0-only**), `bsl-analyzer` (LGPL/GPL/Apache/MIT),
`rlm-bsl-mcp` и `rlm-bsl-index` (MIT).

Порт **вызывает** эти бинарники отдельными процессами и не линкует их, поэтому
цепочка лицензий апстрима не меняется. Но `bootstrap/` в этой сборке скопирован
из пакета unica: при публикации порта как отдельного продукта подтвердите право
на распространение этих бинарников либо замените их на скачивание из релизов
апстрима.

Один Rust-патч, который не обязателен, но заметно чище: добавить в
`crates/unica-bootstrap/src/host/descriptor.rs` дескриптор хоста `DSH`
(корень кэша `$DSH_HOME/unica`, пустой `manifest_dir`). Апстрим-модуль прямо
описывает третий хост как добавление одной записи в `KNOWN`. Порт намеренно
обходится без этого: путь `run` берёт корень плагина аргументом и таблицу
хостов не читает.
