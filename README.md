# unica for DeepSeek Harness

Порт публичного плагина **[Unica](https://github.com/IngvarConsulting/unica)**
на **[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)**.

Unica — инструментарий разработки на 1С:Предприятии: 76 навыков и один
stdio MCP-сервер с 74 инструментами для метаданных, форм, ролей, СКД и MXL,
внешних обработок и отчётов, сборки и обновления информационных баз, поиска и
диагностики BSL-кода. Апстрим поддерживает Codex и Claude Code; DSH в нём не
поддерживается, поэтому этот репозиторий — интеграционный слой.

**Код апстрима не изменяется и не форкается.** Переписывается ровно одно:
пространство имён инструментов (см. [Как это работает](#как-это-работает)).

## Возможности

74 инструмента сгруппированы в 22 домена:

| Домен | Шт | Назначение |
|---|---|---|
| `unica.runtime` | 7 | запуск 1С, длительные задания: `execute`, `job.start/status/wait/logs/cancel/list` |
| `unica.form` | 6 | управляемые формы: `add`, `edit`, `remove`, `compile`, `info`, `validate` |
| `unica.code` | 6 | BSL-код: `search`, `definition`, `outline`, `graph`, `patch`, `diagnostics` |
| `unica.cfe` | 5 | расширения конфигурации: `init`, `borrow`, `patch_method`, `diff`, `validate` |
| `unica.build` | 5 | сборка и ИБ: `make`, `load`, `dump`, `update`, `run` |
| `unica.source` | 5 | исходники: `resolve`, `locate`, `read`, `children`, `resources` |
| `unica.cf` / `unica.meta` | 4+4 | конфигурация и объекты метаданных: `info`, `add`, `edit`, `remove`, `validate` |
| `unica.dcs` / `unica.mxl` | 4+4 | СКД и табличные документы: `compile`, `decompile`, `edit`, `info`, `validate` |
| `unica.role` / `unica.subsystem` | 4+4 | роли и подсистемы |
| прочие | 16 | `interface`, `template`, `xdto`, `help`, `support`, `project`, `epf`, `erf`, `standards`, `documentation` |

76 навыков покрывают как «как это сделать» (`cf-edit`, `form-compile`,
`dcs-compile`, `cfe-patch-method`, `code-patch`), так и «что именно строить»:
`metadata-modeling`, `register-design`, `document-posting`, `object-events`,
`form-events`, `module-placement`, `transactions-locks`, `object-locks`,
`query-optimize`, `security-auth-crypto`, `data-separation`, `api-design`,
`test-authoring`.

## Требования

- **Node.js** — установщик и упаковщик.
- **DSH** — установленный и запускаемый (`dsh web`, `dsh --profile headless` и т.д.).
- **1С:Предприятие** — только для операций, которые реально запускают платформу
  (`unica.build.*`, `unica.runtime.*`). Чтение метаданных, разбор форм, СКД и
  MXL, поиск и диагностика BSL работают без неё.
- **Сеть при первом запуске** — ядро unica (~100 МБ) скачивается с GitHub.
  Дальше всё офлайн.
- **Платформы** — Windows x64, Linux x64, macOS arm64.

## Установка

```sh
git clone https://github.com/malinovme/dsh-unica.git
cd dsh-unica/dsh-unica-plugin
node install.mjs --target both
```

Установщик сам определит `$DSH_HOME` (`~/.dsh`), ОС и способ запуска, и
пропишет абсолютные пути вашей машины. Затем **начните новую сессию DSH и
выберите пресет «Unica 1C»**.

### Варианты установки

| Команда | Что делает |
|---|---|
| `node install.mjs` | только агент-пресет для Web GUI (по умолчанию) |
| `node install.mjs --target both` | ещё и патч профиля `headless` |
| `node install.mjs --profile tui` | патч для другого профиля |
| `node install.mjs --dsh-home D:\other` | нестандартный `$DSH_HOME` |
| `node install.mjs --dry-run` | показать план, ничего не записывать |

**Какой вариант нужен.** Web GUI собирает сессии из агент-пресета, поэтому для
него нужен `--target preset`. Профили `headless`, `tui`, `sdk`, `acp` пресетами
не пользуются — им достаточно `--target profile`. `--target both` закрывает оба
случая.

### Как выбрать пресет

1. **Обновите страницу в браузере** (F5). Список пресетов не отслеживает
   изменения файлов на диске, а установщик пишет их снаружи.
2. В новом диалоге нажмите чип выбора агент-пресета в стартовой области и
   выберите **Unica 1C**. Либо откройте **Settings → Agent presets** и нажмите
   **Set as default** на этой карточке, чтобы пресет применялся ко всем новым
   сессиям.
3. Убедиться, что применилось, можно по шапке сессии — там показан её пресет.

В **уже идущей** сессии пресет не сменится: состав фиксируется при создании.
Нужен новый диалог.

## Использование

Отдельных команд заучивать не нужно: навыки и инструменты подключаются к
модели автоматически. Достаточно ставить задачу по-русски.

**Через навык** — когда нужен рабочий процесс, а не один вызов:

```
Добавь в конфигурацию справочник Валюты с реквизитами Код и Наименование
и создай форму элемента
```

```
Найди в проекте обработку закрытия месяца и проверь модуль на ошибки
```

```
Спроектируй регистр накопления для учёта продаж
```

**Прямым вызовом инструмента** — модель вызывает `unica.*` как обычные
инструменты DSH:

| Задача | Инструмент |
|---|---|
| Какие наборы исходников есть в проекте | `unica.project.map` |
| Прочитать объект метаданных | `unica.meta.info` |
| Найти код | `unica.code.search` |
| Диагностика модуля | `unica.code.diagnostics` |
| Собрать EPF | `unica.build.make` |
| Загрузить ИБ из исходников | `unica.build.load` |
| Запустить 1С | `unica.runtime.execute` |
| Долгая операция в фоне | `unica.runtime.job.start` → `job.status` / `job.wait` |

Полная карта имён — [`dsh-unica-plugin/tool-map.json`](dsh-unica-plugin/tool-map.json).

Прямой вызов выглядит как обычный вызов инструмента DSH — например, компиляция
формы из JSON-описания:

```json
{
  "cwd": "<workspace>",
  "JsonPath": "<описание формы>.json",
  "OutputPath": "<Form.xml>",
  "dryRun": false
}
```

уходит в `mcp__unica__unica_form_compile_bf4ab47aa393`. У мутирующих
инструментов **предпросмотр — это дефолт**: `dryRun: true`, если не сказано
иное. `dryRun: false` навыки выставляют только тогда, когда изменение
запрошено явно.

### Что полезно знать при работе

- **Длинные операции — через задания.** `unica.runtime.execute` выполняется
  синхронно в рамках одного вызова; для сборки и обновления ИБ используйте
  `unica.runtime.job.start` и наблюдайте через `status` / `wait` / `logs`.
- **Логические адреса вместо путей.** Инструменты адресуют объекты парой
  `sourceSet` + `metadataPath`. `sourceSet` — имя набора исходников из
  `v8project.yaml` (не константа); его выдаёт `unica.project.map`. Путь к файлу,
  найденный другими средствами, переводится в логический адрес через
  `unica.source.locate`.
- **Права.** Режим `workspace-write` не даст писать в исходники 1С вне текущего
  workspace и в кэш unica. Для реальной работы нужен профиль с более широкими
  правами.

## Обновление

```sh
cd dsh-unica/dsh-unica-plugin   # или новая версия из архива
node install.mjs --target both
```

Затем новая сессия DSH. Обновление апстрима до новой версии unica:

```sh
UNICA_UPSTREAM_VERSION=0.13.0 node tools/build-skills.mjs
```

## Перенос на другую машину

Абсолютные пути в репозитории не хранятся — их подставляет установщик, поэтому
достаточно скопировать каталог и переустановить:

```sh
node install.mjs --target both
```

Сборка архива:

```sh
node package.mjs                     # 0.4 МБ — без бинарников bootstrap
node package.mjs --include-bootstrap # 4.4 МБ — самодостаточный
```

Рядом кладётся `<архив>.sha256.json` с контрольной суммой и списком файлов.

## Удаление

```powershell
Remove-Item -Recurse "$env:USERPROFILE\.dsh\.agent-presets\unica-1c"
Remove-Item "$env:USERPROFILE\.dsh\profiles\headless\cordis.patch.yml"
```

Кэш ядра в `$DSH_HOME/unica/runtimes` можно оставить — он переиспользуется при
повторной установке. Удалите его, если хотите освободить ~300 МБ.

## Как это работает

Два шва несут весь порт.

**Навыки.** DSH требует во frontmatter `name` и `description` и молча
игнорирует незнакомые ключи, поэтому апстримные `SKILL.md` загружаются без
правок — кроме пространства имён инструментов. DSH публикует MCP-инструменты
как `mcp__<сервер>__<имя>`, заменяя символы вне `[A-Za-z0-9_-]` на `_` и
дописывая 12 hex-символов SHA-256 при такой потере информации:

```
unica.cf.init            -> mcp__unica__unica_cf_init_60b2c7880b08
unica.runtime.job.cancel -> mcp__unica__unica_runtime_job_cancel_8b0b07231c28
```

Переписано 1011 ссылок в 81 файле.

**MCP.** `dsh-mcp-client` запускает поставляемый `unica-bootstrap`, который
сверяет закреплённый `runtime-manifest.json` (SHA-256 архива и каждого файла),
атомарно публикует ядро в кэш и только потом запускает единственный
stdio-процесс `unica`. Запуск ядра из кэша напрямую прошёл бы мимо проверки.

Способ запуска выбирается по платформе: на Windows — напрямую
`unica-bootstrap.exe`, на macOS и Linux — `sh bootstrap/launch.sh`, где апстрим
сам разбирает ОС и архитектуру.

### Структура

```
dsh-unica-plugin/
  skills/            76 навыков, 87 файлов, 647 КБ
  references/        48 справочных документов, 919 КБ
  bootstrap/         нативные лаунчеры: darwin-arm64, linux-x64, win-x64
  tools/             сопровождение (см. ниже)
  install.mjs        установка в $DSH_HOME
  package.mjs        сборка архива
  cordis.patch.yml   шаблон патча профиля
  tool-map.json      карта 74 инструментов
  runtime-manifest.json  закреплённый релиз апстрима с хешами
```

## Проверки

```sh
cd dsh-unica-plugin
node tools/check-refs.mjs .                      # 61 ссылка навыков на справочники
node tools/check-encoding.mjs skills references  # кодировка портированных файлов
node tools/surface-summary.mjs .                 # сводка: домены инструментов и навыки
node tools/check-port-notes.mjs                  # правки порта на месте и целы
node tools/check-preset.mjs <agent.cordis.yml>   # пресет парсится, правила сессии на месте
node tools/ci-dryrun.mjs                         # весь CI-прогон локально, без пуша
```

Все они — не формальность. Первая ловит рассогласование навыков и справочного
корпуса, вторая — порчу UTF-8 при копировании (навыки почти сплошь
русскоязычные), остальные защищают правки порта от тихой потери.

## Правки порта поверх апстрима

Порт не форкает unica, но у четырёх инструментов поведение расходится с тем,
что обещает собственная документация проекта. Эти расхождения записаны прямо в
навыки как разделы «Правка порта», чтобы агент не тратил время на тупиковый
путь:

| Навык | Что записано |
|---|---|
| `unica-v8-runner` | Сбой чтения файла-списка при частичной загрузке **не** вызывает автоматический полный повтор — повторять сразу с `fullRebuild: true` |
| `unica-register-design` | `meta.add`/`meta.edit` не принимают `RegisterType`: генератор пишет `Balance`, для `Turnovers` нужна правка XML |
| `unica-role-compile` | Обновить существующую роль инструментами нельзя: `role.edit` без `cwd` падает, `role.compile` пропускает существующую роль даже с `force` |
| `unica-code-patch` | Вызов без `cwd` ищет источник в домашнем каталоге и падает с `SourceSetNotFound` |

Три из них дополнительно попадают в персону пресета — то есть действуют в
каждой сессии, а не только когда загружен соответствующий навык. Правила
встраиваются в `suffix` существующей строки `persona`: вторая строка `persona`
невозможна, `dsh-persona` регистрирует имена секций глобально и падает на
коллизии.

Исходники правок — таблица `PORT_NOTES` в `tools/build-skills.mjs`. Она
применяется **до** переименования инструментов, поэтому внутри правки имя
пишется обычным образом (`role.edit`), а в результат попадает уже
`mcp__unica__unica_role_edit_…`. Если апстрим переименует якорь
`## MCP routing` или изменит `suffix` в шаблоне пресета, генерация и установка
упадут с явной ошибкой — тихой потери правок не будет.

## Известные ограничения

- **`startup_timeout_sec` DSH не поддерживает.** Первая закачка ядра может не
  уложиться в 60-секундное окно MCP SDK, и тогда сервер поднимется только со
  второй попытки — `reconnect` включён по умолчанию и доведёт подключение до
  конца. Отдельной команды предзагрузки в этой версии bootstrap нет (`unica-bootstrap`
  знает только `run` и `verify`), поэтому для закрытого контура кэш наполняют на
  машине с доступом и переносят каталог `$DSH_HOME/unica/runtimes` целиком.
- **74 инструмента в каждом запросе** — заметная постоянная надбавка к
  токенам. Если дорого, сузьте набор до нужных доменов.
- **`allowed-tools` из навыков не действует** — DSH не читает этот ключ
  frontmatter, поэтому ограничения набора инструментов не применяются.
- **`epf-bsp-add-command`** — единственный навык без ссылок на MCP: он
  инструктирует работать напрямую через `Read`/`Edit`/`Glob`/`Grep`.
- **Ветка `launch.sh`** (macOS/Linux) не проверена натурно: в песочнице, где
  готовился порт, Git-bash не стартует. Генерация конфига для неё проверена
  через `--dump-config`; сам скрипт апстримный и портом не изменялся.

## Лицензии

Собственный код Unica — **LGPL-3.0-or-later**
([`LICENSE`](dsh-unica-plugin/LICENSE)). Поставляемые бинарники сохраняют свои
лицензии, включая **AGPL-3.0-only** для `v8-runner`; полный разбор —
[`ATTRIBUTIONS.md`](dsh-unica-plugin/ATTRIBUTIONS.md).

Порт вызывает эти бинарники отдельными процессами и не линкует их, поэтому
лицензионная цепочка апстрима не меняется. При распространении сборки
учитывайте, что `bootstrap/` — прекомпилированные бинарники апстрима.
