# unica for DeepSeek Harness

Порт публичного плагина **[Unica](https://github.com/IngvarConsulting/unica)**
на **[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)**.

Unica — инструментарий разработки на 1С:Предприятии: 55 навыков и один
stdio MCP-сервер с 11 инструментами для метаданных, форм, ролей, СКД и MXL,
внешних обработок и отчётов, сборки и обновления информационных баз, поиска и
диагностики BSL-кода. Апстрим поддерживает Codex и Claude Code; DSH в нём не
поддерживается, поэтому этот репозиторий — интеграционный слой.

**Код апстрима не изменяется и не форкается.** Переписывается ровно одно:
пространство имён инструментов (см. [Как это работает](#как-это-работает)).

## Версия и артефакты

Порт отслеживает апстрим схемой `<upstream>`, а собственные пересборки нумерует
ревизиями: `0.15.0.1` — первая ревизия порта на Unica 0.15.0-rc.1.

| | |
|---|---|
| Unica | **0.15.0-rc.1** |
| Ревизия порта | 1 |
| Инструментов MCP | **11** |
| Навыков | **55** |
| Файлов справочников | **48** |
| `v8-runner` | **0.15.3** |

Апстрим выпустил 0.13.0 9 октября 2026 и переработал поверхность: 74 действия
свелись к 11 инструментам, навыков стало 55 вместо 76, релиз стал публиковать
архив рантайма вместо бинарников bootstrap. Порт переписан под неё, линия 0.12
больше не поддерживается.

С 0.15.0-rc.1 (26 октября 2026) поверхность не менялась — те же 11 инструментов,
поэтому навыки и карта имён остались как есть. Что изменилось по существу:

- **Провайдер `kb-1ci` убран из `unica.docs`** — в 0.13 он стабильно падал по
  таймауту на этой машине и стоил ~35 с на каждый вызов; теперь `docs` отвечает
  за секунды и отдаёт `platform-syntax-help` и `v8std`.
- **Диагностика BSL работает.** Первый вызов `unica.check` на модуле после старта
  сервера может ответить «BSL analysis did not complete … Repeat the call» —
  это прогрев индекса; повторный вызов возвращает настоящие диагностики
  (`validators: ["bsl"]`). На сценарном модуле проверка нашла реальное нарушение
  стандарта (`CommonModuleInvalidType`) и после `props.set` стала `passed` — см.
  [platform-findings.md](docs/platform-findings.md).
- **`v8-runner` обновлён до 0.15.3** (был 0.14.0), ядро выросло до 40 МБ.
- Зависание `1cv8`, запущенного раннером, обновление **не вылечило**, но причина
  оказалась не в версии: рантайм лежал в рабочем каталоге и унаследовал Low-метку
  песочницы DSH (см. [platform-investigation.md](docs/platform-investigation.md)).

## Возможности

- **Навыки Unica как навыки DSH** — 55 каталогов, все ссылки на справочники
  сохранены.
- **Один MCP-сервер `unica`** — 11 инструментов: `view`, `apply`, `resolve`,
  `search`, `check`, `diff`, `run`, `docs`, `task.get/result/cancel`.
- **Адресация через `at`** — `<sourceSet>:<Kind>[.<Name>...]` вместо путей.
- **План перед записью** — `apply` возвращает `executionToken` и меняет файлы
  только повторным вызовом с этим токеном.
- **Родные инструменты DSH** — модель видит их как `mcp__unica__…`, рядом с
  `read`, `write` и остальными.

## Требования

- **Node.js** — установщик, лаунчер и упаковщик.
- **DSH 0.2.0 или новее** — установленный и запускаемый (`dsh web`,
  `dsh --profile headless` и т.д.).
- **1С:Предприятие** — только для операций, которые реально запускают платформу.
  Чтение метаданных, разбор форм, СКД и MXL, поиск и диагностика BSL работают без
  неё.
- **Сеть при первом запуске** — ядро unica (~10 МБ), а затем движки
  (`bsl-analyzer`, `rlm-bsl-*`, `v8-runner`) по требованию. Дальше всё офлайн.
- **Платформы** — Windows x64, Linux x64, macOS arm64.

## Установка

**Одной командой** — скачает релизный архив, сверит SHA-256, распакует плагин и
сразу проверит, что MCP-сервер поднимается:

```sh
# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/malinovme/dsh-unica/main/install.sh | sh
```

Для приватного репозитория на macOS / Linux сначала авторизуйте GitHub CLI
командой `gh auth login --hostname github.com` (аккаунт должен иметь доступ к
репозиторию), затем выполните:

```sh
gh api -H "Accept: application/vnd.github.raw+json" repos/malinovme/dsh-unica/contents/install.sh | sh
```

Авторизованный `gh` скачивает архив и манифест SHA-256 выбранного релиза.
Без авторизованного `gh` скрипт использует `curl` (или `wget`) для публичного
репозитория. Чтобы закрепить версию, передайте её именно процессу `sh`:

```sh
gh api -H "Accept: application/vnd.github.raw+json" repos/malinovme/dsh-unica/contents/install.sh | UNICA_VERSION=v0.12.3.3 sh
```

```powershell
# Windows
irm https://raw.githubusercontent.com/malinovme/dsh-unica/main/install.ps1 | iex
```

Скрипт сам выбирает профиль (`desktop`, если он есть, иначе `web`), а если
каталог кэша отказывает демону сервера — переносит кэш без вашего участия.
Требуется только Node.js, который и так нужен DSH.

**Если у вас стоят и Desktop, и Web GUI** — скрипт выберет `desktop`; чтобы
поставить в оба, вызовите его дважды с `UNICA_PROFILE=web` и
`UNICA_PROFILE=desktop`. Разбор развилки — в
[README плагина](dsh-unica-plugin/README.md#какой-профиль-получит-установку).

**Из исходников** — если хотите править порт или у вас нет доступа к релизам:

```sh
git clone https://github.com/malinovme/dsh-unica.git
cd dsh-unica/dsh-unica-plugin
node install.mjs --target both --verify
```

**Вручную из архива** — архив раскрывается без обёртки, его содержимое и есть
каталог плагина:

```sh
tar -xzf dsh-plugin-unica.tar.gz && node install.mjs --verify
```

Установщик сам определит `$DSH_HOME` (`~/.dsh`), ОС и способ запуска, и пропишет
абсолютные пути вашей машины. Флаг `--verify` поднимает MCP-сервер и печатает
результат — `ok serverInfo unica 0.13.0, 11 tools`; без него установка проверяет
только записанные файлы.

Затем **перезапустите сервер DSH** и **начните новую сессию**, выбрав пресет
**«Unica 1C»**.

### Варианты установки

| Команда | Что делает |
|---|---|
| `node install.mjs` | только агент-пресет для Web GUI (по умолчанию) |
| `node install.mjs --verify` | то же плюс проверка: поднимает MCP-сервер и печатает результат |
| `node install.mjs --cache-dir D:\unica-cache` | перенести кэш, если каталог по умолчанию отказывает демону |
| `node install.mjs --workspace D:\proj\ib` | закрепить каталог проекта: без него переподключение сервера берёт каталог профиля |
| `node install.mjs --target both` | ещё и патч профиля `headless` |
| `node install.mjs --target preset --profile desktop` | установка в **DSH Desktop** |
| `node install.mjs --dry-run` | показать план, ничего не записывать |

> **Не размещайте кэш рантайма внутри рабочего каталога.** DSH помечает файлы в
> рабочем каталоге низкой целостностью (Low), и метка наследуется на всё, что там
> создаётся. `v8-runner.exe` из такого кэша запускается с Low-токеном, а его дети
> — `1cv8`, `ibcmd` — не могут писать в профиль пользователя, куда 1С обязана
> писать (`%LOCALAPPDATA%\1C\1cv8`). Симптомы: `ibcmd` падает с «доступ запрещён»
> или ошибкой `standalone-server/lock.pid`, а `1cv8 DESIGNER` зависает, потребляя
> процессор. Держите кэш вне рабочего каталога — по умолчанию он и так лежит в
> `$DSH_HOME/unica/runtimes`.

**Какой вариант нужен.** Web GUI и DSH Desktop собирают сессии из агент-пресета,
поэтому им нужен `--target preset` (у Desktop дополнительно `--profile desktop`).
Профили `headless`, `tui`, `sdk`, `acp` пресетами не пользуются — им достаточно
`--target profile`. `--target both` закрывает оба случая. Если ставите скриптом
`install.sh`/`install.ps1`, всё это он выбирает сам.

### Как выбрать пресет

Пресет — это строка плагина в `cordis.patch.yml` профиля, а не каталог на диске:
так устроен DSH 0.2.0 (в 0.1.x пресеты сканировались из
`$DSH_HOME/.agent-presets`, и этот механизм удалён). Поэтому список пресетов
пересобирается при загрузке профиля:

1. **Перезапустите сервер `dsh web`** (или приложение DSH Desktop).
2. **Начните новую сессию** — состав сессии фиксируется при её создании.

Пресет называется **«Unica 1C»**. Если его нет в списке — см.
[Известные ограничения](#известные-ограничения) и диагностику в
[README плагина](dsh-unica-plugin/README.md).

## Использование

После выбора пресета модель видит 11 инструментов `unica` и 55 навыков. Типичный
цикл работы:

```
resolve → view → apply (план) → apply (executionToken) → check
```

- `resolve` называет доступные source set'ы;
- `view` читает узел по адресу `at`;
- `apply` с `at` и `ops` строит план и возвращает `data.executionToken`;
- повторный `apply` только с токеном исполняет сохранённый план;
- `check` запускает все валидаторы вида узла;
- `docs` отдаёт контракты аргументов — по проводу они не приходят;
- `run` — запуск операций, `task.*` — длинные задания, `diff` и `search` —
  разбор и поиск.

### Что полезно знать при работе

- **`cwd` больше нет.** Адрес узла передаётся в `at`, рабочее пространство берётся
  из сессии.
- **`apply` без токена ничего не пишет.** Это и есть dry run по умолчанию.
- **Первый вызов движка требует сети** и заметно дольше остальных.
- **`*.validate` не существует.** Валидация — через `check`.
- **Права шире песочницы** нужны для правки исходников 1С вне рабочего каталога.

## Как это работает

Порт не форкает Unica. Навыки и справочники — копия апстрима, а единственное
семантическое изменение — имена инструментов.

Unica называет инструменты с точками (`unica.view`). DSH публикует MCP-инструмент
как `mcp__<server>__<имя>`, а при потере информации в нормализации дописывает
12 hex-символов SHA-256 от `"<server>\0<raw name>"`:

```
unica.view  ->  mcp__unica__unica_view_6f3a42290cc8
```

Формула проверена по исходникам `dsh-mcp-client`. Карта соответствия —
`tool-map.json`, переписывание — `tools/build-skills.mjs` (666 ссылок в 58
файлах). Навык, упомянувший имя вне карты, валит генерацию.

**Слой запуска** — свой, на Node (`bootstrap/launch.mjs`). С 0.13 манифест
описывает не один архив, а **артефакты**: ядро и движки, которые Unica берёт
извне — `bsl-analyzer`, `rlm-tools-bsl`, `v8-runner`. Лаунчер ставит каждый в
стандартную раскладку кэша

```
<cache>/<artifact>/<version>--<asset sha256>/<target>/
```

сверяет SHA-256 скачанного ассета, распаковывает во временный каталог, пишет
маркер `.ready.json` и только потом переименовывает каталог в место. Затем
передаёт управление серверу. Порт по-прежнему не поставляет исполняемых файлов:
всё скачивается в кэш при первом запуске, поэтому лицензии движков (AGPL у
`v8-runner`, LGPL у `bsl-analyzer`) не превращаются в обязательства
распространения.

**Раскладку нельзя угадать.** Unica ищет движки не рядом с собой, а в кэше
артефактов, и узнаёт о нём из `UNICA_ARTIFACT_CACHE` — лаунчер выставляет её
серверу. Без переменной любой вызов, которому нужен движок, отвечает
`bundled_tool_missing` и указывает на `<runtime>/bin/win-x64/v8-runner`, куда
ничего класть не надо. Манифест не пишется руками: `node
tools/build-runtime-manifest.mjs` собирает его из `third-party/tools.lock.json`
(проверка на устаревание — `--check`).

**Релей ответов.** Лаунчер не отдаёт stdio сервера напрямую: он построчно читает
`tools/call`-ответы и, если успешный ответ пришёл с пустым `content` и полезной
нагрузкой только в `structuredContent`, подставляет её одним текстовым блоком.
Иначе DSH — он проецирует модели только `content` — показывает
`(unica.view returned no model-visible content)` и не пускает в кадр ни
`executionToken`, ни `can`-словарь узла, ни `next`-подсказки, ни `taskId`. Ошибки
Unica и так дублирует текст, поэтому до правки ломались ровно успешные вызовы.
`structuredContent` остаётся нетронутым, ответы с собственным текстом проходят
байт в байт.

| Переменная | Смысл |
|---|---|
| `UNICA_BRIDGE_TEXT_FALLBACK=0` | отключить релей, вернуть сырой stdio |
| `UNICA_WORKSPACE_ROOT=<путь>` | закрепить каталог, в котором стартует сервер |
| `UNICA_ARTIFACT_DELIVERY=background\|eager\|off` | докачка движков: за сервером (по умолчанию), до старта, или никогда |
| `UNICA_LAUNCH_SELFTEST_COMMAND=<json argv>` | тестовый хук: подменить рантайм |

Доставка по умолчанию не блокирует старт: сервер поднимается сразу, движки
приезжают следом (`v8-runner` 4 МБ, затем `bsl-analyzer` и `rlm-tools-bsl` по
требованию). Вызов, которому движок нужен до его появления, честно ответит
`bundled_tool_missing` — повторите его после `unica launcher: <engine> delivered`
в журнале сервера.

Закрепление рабочего каталога стоит включать, если сервер перезапускается
переподключением: Unica берёт workspace из каталога запуска, а DSH стартует
упавшее соединение из каталога профиля — без закрепления проект молча
подменяется на `$DSH_HOME/profiles/<profile>`. Проверка релея, закрепления и
защиты доставки — `node tools/verify-bridge.mjs` (режим `--fake` без сети;
живые движки включаются `UNICA_TEST_ENGINES=1` и `UNICA_TEST_WORKSPACE=<проект>`).

### Структура

```
dsh-unica-plugin/
  install.mjs            установщик: профили, патчи, проверка
  bootstrap/launch.mjs   лаунчер: скачивает и запускает сервер
  runtime-manifest.json  дескрипторы рантайма на три цели
  tool-map.json          11 инструментов: raw -> публичное имя DSH
  skills/                55 навыков unica-*
  references/            48 справочников
  tools/                 генератор навыков и проверки
install.sh / install.ps1 установка одной командой
.github/workflows/       CI: проверки и режимы файлов
```

## Обновление порта на новый апстрим

1. Прочитать changelog апстрима и **проверить, что он публикует архивы рантайма**
   под `darwin-arm64`, `linux-x64`, `win-x64` — без них порт не соберётся.
2. Склонировать апстрим и посмотреть, что стало с навыками и справочниками.
3. Обновить `runtime-manifest.json` из релизных дескрипторов.
4. Пересчитать `tool-map.json` по живому `tools/list` (формула выше).
5. `UNICA_UPSTREAM_PLUGIN=<путь> node tools/build-skills.mjs` — перегенерировать
   навыки; генератор упадёт, если появятся неизвестные имена инструментов.
6. Перечитать правила в персоне (`install.mjs`) — они описывают контракт
   инструментов и устаревают вместе с ним.
7. Прогнать `--verify` и проверки, пересобрать архив, выпустить релиз.

## Удаление

```sh
rm -rf ~/.local/share/unica-plugin        # macOS / Linux
rm -rf $DSH_HOME/unica                    # кэш рантайма и состояние демона
```

и удалить строки порта из `cordis.patch.yml` нужного профиля: `preset-unica-1c`
в пресетном, `mcp-unica` и `skill-filesystem-unica` — в остальных.

## Известные ограничения

- **macOS натурно не проверялась.** Код общий с Windows и Linux, но прогона на
  маке не было; первый запуск стоит делать с `--verify`.
- **macOS arm64 only** — Intel-маки апстрим не покрывает.
- **Справочники апстрима** упоминают десять имён инструментов 0.12 в спеках форм и
  DSL. Это документация, а не инструкции; порт её не переписывает, чтобы не
  выдавать догадку за текст апстрима.
- **Пресет не виден в списке** — почти всегда значит, что MCP-сервер не поднялся.
  Запустите `node install.mjs --verify`: он назовёт причину, а при отказе каталога
  перенесёт кэш сам.
