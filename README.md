# unica for DeepSeek Harness

Порт публичного плагина **[Unica](https://github.com/IngvarConsulting/unica)**
на **[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)**.

Unica — инструментарий разработки на 1С:Предприятии: 50 навыков и один
stdio MCP-сервер с 11 инструментами для метаданных, форм, ролей, СКД и MXL,
внешних обработок и отчётов, сборки и обновления информационных баз, поиска и
диагностики BSL-кода. Апстрим поддерживает Codex и Claude Code; DSH в нём не
поддерживается, поэтому этот репозиторий — интеграционный слой.

Порт поднимает unica **на каждый рабочий каталог сессии**: один профиль DSH
обслуживает сколько угодно проектов, и `unica.search`/`check`/`view` всегда
смотрят в тот каталог, из которого пришёл вызов.

**Код апстрима не изменяется и не форкается.** Переписывается ровно одно:
пространство имён инструментов (см. [Как это работает](#как-это-работает)).

## Возможности

- **Навыки Unica как навыки DSH** — 50 каталогов, все ссылки на справочники
  сохранены.
- **Нативный мост к `unica`** — 11 инструментов: `view`, `apply`, `resolve`,
  `search`, `check`, `diff`, `run`, `docs`, `task.get/result/cancel`.
  При активации мост читает все страницы каталога MCP. Во время вызова он обрабатывает встречный `ping`, даже если сервер использует тот же идентификатор запроса.
- **Рабочий каталог на каждый вызов** — мост берёт его из сессии DSH и держит
  пул процессов unica по каталогам, поэтому две сессии в разных проектах видят
  разные кодовые базы.
- **Адресация через `at`** — `<sourceSet>:<Kind>[.<Name>...]` вместо путей.
- **План перед записью** — `apply` возвращает `executionToken` и меняет файлы
  только повторным вызовом с этим токеном.
- **Родные инструменты DSH** — модель видит их как `mcp__unica__…`, рядом с `read`, `write` и остальными.

## Требования

- **Node.js** — установщик, лаунчер и упаковщик.
- **DSH 0.2.2-rc.1 или новее** — мост использует сервис рабочего каталога сессии.
- **1С:Предприятие** — только для операций, которые реально запускают платформу.
  Чтение метаданных, разбор форм, СКД и MXL, поиск и диагностика BSL работают без
  неё.
- **Сеть при первом запуске** — ядро unica (17–20 МБ), а затем движки
  (`v8-runner`, `bsl-analyzer`) в фоне. Следующие запуски используют кэш.
- **Платформы** — Windows x64, Linux x64, macOS arm64.

## Совместимость с DSH

Мост получает каталог сессии через `ctx.workingDirectory`. Установщик добавляет правила Unica в `suffix` строки `persona` выбранного профиля.

## Установка

**Одной командой** — скачает релизный архив, сверит SHA-256, распакует плагин и
сразу проверит, что unica поднимается и отвечает:

```sh
# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/malinovme/dsh-unica/main/install.sh | sh
```

```powershell
# Windows
irm https://raw.githubusercontent.com/malinovme/dsh-unica/main/install.ps1 | iex
```

Чтобы закрепить версию, передайте её процессу `sh` (для Windows — параметр
`-Version`):

```sh
curl -fsSL https://raw.githubusercontent.com/malinovme/dsh-unica/main/install.sh | UNICA_VERSION=vX.Y.Z.N sh
```

Скрипт сам выбирает профиль (`desktop`, если он есть, иначе `web`), а если
каталог кэша отказывает демону сервера — переносит кэш без вашего участия.
Для распаковки архива установщику нужен `tar`, а для запуска плагина — Node.js.
Для блокировки параллельного обновления `install.sh` использует `flock` или Perl.

**Если у вас стоят и Desktop, и Web GUI**, запустите установщик для каждого профиля.
В `install.sh` профиль задаётся переменной `UNICA_PROFILE` (`web` или `desktop`).
В PowerShell сохраните `install.ps1` и запустите `.\install.ps1 -Profile web`,
затем `.\install.ps1 -Profile desktop`. Подробнее о выборе профиля — в
[README плагина](dsh-unica-plugin/README.md#какой-профиль-получит-установку).

**Из исходников** — если хотите править порт:

```sh
git clone https://github.com/malinovme/dsh-unica.git
cd dsh-unica/dsh-unica-plugin
node install.mjs --target both --verify
```

**Вручную из архива** — архив раскрывается без обёртки, его содержимое и есть
каталог плагина:

```sh
tar -xzf dsh-plugin-unica.tar.gz && node install.mjs --verify
```

Установщик сам определит `$DSH_HOME` (`~/.dsh`), ОС и способ запуска, и пропишет
абсолютные пути вашей машины. Флаг `--verify` запускает мост в каталоге проверки
до записи профилей и печатает результат — `native check : ok  serverInfo unica <версия>, 11
tools in … ms, workspace …`; без него установка проверяет только записанные
файлы.

Затем **перезапустите сервер DSH** и **начните новую сессию**, выбрав пресет
**«Unica 1C»**.

### Варианты установки

| Команда | Что делает |
|---|---|
| `node install.mjs` | только агент-пресет для Web GUI (по умолчанию) |
| `node install.mjs --verify` | то же плюс самопроверка: поднимает unica и читает `unica.view {}` |
| `node install.mjs --cache-dir D:\unica-cache` | перенести кэш, если каталог по умолчанию отказывает демону |
| `node install.mjs --verify-cwd D:\proj\ib` | каталог, в котором `--verify` проверяет мост |
| `node install.mjs --target both` | ещё и патч профиля `headless` |
| `node install.mjs --target preset --profile desktop` | установка в **DSH Desktop** |
| `node install.mjs --dry-run` | показать план, ничего не записывать |

> **Не размещайте кэш рантайма внутри рабочего каталога.** DSH помечает файлы в
> рабочем каталоге низкой целостностью (Low), и метка наследуется на всё, что там
> создаётся. `v8-runner.exe` из такого кэша запускается с Low-токеном, а его дети
> — `1cv8`, `ibcmd` — не могут писать в профиль пользователя, куда 1С обязана
> писать (`%LOCALAPPDATA%\1C\1cv8`). Симптомы: `ibcmd` падает с «доступ запрещён»
> или ошибкой `standalone-server/lock.pid`, а `1cv8 DESIGNER` зависает, потребляя
> процессор. Держите кэш вне рабочего каталога — по умолчанию он и так лежит в
> `$DSH_HOME/unica/runtimes`.

**Какой вариант нужен.** Web GUI и DSH Desktop собирают сессии из агент-пресета,
поэтому им нужен `--target preset` (у Desktop дополнительно `--profile desktop`).
Для `headless`, `tui`, `sdk` и `acp` укажите `--target profile --profile <имя>`.
Команда `node install.mjs --target both` по умолчанию устанавливает пресет в
`web` и строки плагина в `headless`. Скрипты `install.sh` и `install.ps1`
по умолчанию устанавливают пресет в выбранный профиль.

При повторной установке ID плагина может быть в кавычках. Установщик сохраняет
комментарий к ID и соседние пользовательские строки. Если при `--target both`
не удалось записать второй профиль, установщик откатывает запись первого.

#### Настройки нативного моста

В `config` строки `unica-native` можно менять `maxProcesses`, `idleMs`,
`coldStartTimeoutMs`, `startupTimeoutMs` и `toolCallTimeoutMs`. Переустановка
сохраняет эти параметры, а также заданные `serverName`, `nodePath`,
`artifactDelivery`, `probeCwd` и `defaultCwd`. У записи в профиле и записи
внутри пресета могут быть разные значения. Установщик обновляет `name`,
`pluginRoot`, `runtimeCacheDir` и `providerStateDir` по текущему пути плагина
и выбранному расположению кэша.

### Обновление установленной версии

При обновлении скрипт распаковывает релиз рядом с каталогом плагина и проверяет
`install.mjs` и имя пакета. До успешного завершения установки и самопроверки
он хранит прежнюю версию и копию `cordis.patch.yml` выбранного профиля.
Если установка завершилась с ошибкой, скрипт восстанавливает их по прежним
путям. Скачанный кэш рантайма переиспользуется. Для обновления повторите
команду установки:

```sh
curl -fsSL https://raw.githubusercontent.com/malinovme/dsh-unica/main/install.sh | sh
```

Затем перезапустите DSH и начните новую сессию: состав пресета фиксируется при её
создании.

### Восстановление после прерванного обновления

Если процесс установки принудительно завершили, снова запустите установщик для
того же каталога плагина. До обращения к сети он прочитает журнал
`.<имя каталога>.update`. Установщик готовит правки профиля в отдельной копии.
Если установка прервалась до публикации профиля, при следующем запуске вернётся
предыдущая версия плагина, а пользовательские настройки сохранятся. Если проверка
уже завершилась и началась публикация, установщик завершит её. Если профиль
уже совпадает с подготовленным, файл останется на месте. Если пользователь
сохранил другие правки, установщик сохранит их, откатит установку плагина и
сообщит о конфликте. После этого установку можно запустить повторно.

Сообщение о работающем установщике означает, что следует дождаться
завершения процесса, включая его дочерний `install.mjs`. Файл `.update.lock`
может оставаться на диске между запусками.

### Как выбрать пресет

DSH читает пресет из `cordis.patch.yml` при загрузке профиля.

1. **Перезапустите сервер `dsh web`** (или приложение DSH Desktop).
2. **Начните новую сессию** — состав сессии фиксируется при её создании.

Пресет называется **«Unica 1C»**. Если его нет в списке — см.
[Известные ограничения](#известные-ограничения) и диагностику в
[README плагина](dsh-unica-plugin/README.md).

## Использование

После выбора пресета модель видит 11 инструментов `unica` и 50 навыков. Типичный
цикл работы:

```
view {} → view {at} → apply (план) → diff (executionToken) → apply (executionToken) → check
```

- `view {}` показывает рабочий каталог и наборы исходников. `view {at}` читает узел по логическому адресу.
- `resolve` помогает найти логический адрес по пути к файлу исходников.
- `apply` с `at` и `ops` строит план и возвращает `data.executionToken`.
  Передайте токен в `diff`, чтобы посмотреть изменения, затем в `apply`, чтобы записать их.
- `check` запускает валидаторы для выбранного вида узла.
- `docs` ищет по документации 1С. Список операций узла находится в поле `can` ответа
  `view {at}`. Аргументы конкретной операции описаны по адресу `<узел>.Can.<операция>`.
- `search` ищет код и метаданные. `run` запускает операции. Если вызов вернул
  `taskId`, запросите результат через `task.result` с этим идентификатором.

В [учебном проекте «Калькулятор цены»](examples/price-extension/README.md) вы найдёте
объявление BSL-функции и её вызов, добавите пояснение на форму и соберёте
расширение в `.cfe`. Для прохождения урока скачайте или клонируйте ветку `main`:
в ней находятся исходники проекта и готовые запросы.

### Что полезно знать при работе

- **Рабочий каталог** задаётся сессией DSH. В `at` передайте логический адрес узла.
- **`apply` без токена ничего не пишет.** Это и есть dry run по умолчанию.
- **Движки загружаются в фоне.** Для первого обращения дождитесь завершения загрузки нужного движка.
- **Первый `check` после старта сервера прогревает индекс** и может ответить
  «BSL analysis did not complete … Repeat the call» — повторите, это не дефект.
- **`*.validate` не существует.** Валидация — через `check`.
- **Права шире песочницы** нужны для правки исходников 1С вне рабочего каталога.

## Как это работает

Порт не форкает Unica. Навыки и справочники — копия апстрима, а единственное
семантическое изменение — имена инструментов.

Мост преобразует имена Unica в формат DSH `mcp__unica__<имя>`. Если нормализация меняет исходное имя, мост добавляет 12 шестнадцатеричных символов SHA-256 от `"unica\0<raw name>"`. Например:

```
unica.view  ->  mcp__unica__unica_view_6f3a42290cc8
```

Формула реализована в `host/lib/naming.js`. Файл `tool-map.json` содержит соответствия для 11 инструментов. При генерации навыков `tools/build-skills.mjs` проверяет имена по этой карте.

**Каталог на каждый вызов.** У инструмента есть `execute(args, exec)`, и `exec`
несёт агента: мост спрашивает у `ctx.workingDirectory.ensure(exec.agent)` текущий
каталог сессии и берёт процесс unica из пула по этому каталогу. Процесс
запускается по первому вызову. После всплеска параллельных вызовов пул возвращается к `maxProcesses`, завершая наименее недавно использованные свободные процессы. Если каталог проекта заменили по тому же пути, новые вызовы получают новый процесс. Уже начатые вызовы завершаются в прежнем проекте.

**Слой запуска.** Лаунчер на Node.js (`bootstrap/launch.mjs`) читает манифест ядра и движков `bsl-analyzer` и `v8-runner`. Для каждого артефакта используется отдельный каталог кэша.

```
<cache>/<artifact>/<version>--<asset sha256>/<target>/
```

Лаунчер проверяет SHA-256 архива и файлов, записывает маркер `.ready.json` во временный каталог и публикует готовый каталог переименованием. Мост по умолчанию даёт 5 минут на подготовку ядра (`coldStartTimeoutMs`) и 30 секунд на MCP `initialize` после старта ядра (`startupTimeoutMs`).

**Раскладку нельзя угадать.** Unica ищет движки не рядом с собой, а в кэше
артефактов, и узнаёт о нём из `UNICA_ARTIFACT_CACHE` — лаунчер выставляет её
серверу. Без переменной любой вызов, которому нужен движок, отвечает
`bundled_tool_missing` и указывает на `<runtime>/bin/win-x64/v8-runner`, куда
ничего класть не надо. Манифест не пишется руками: `node
tools/build-runtime-manifest.mjs` собирает его из `third-party/tools.lock.json`
(проверка на устаревание — `--check`).

При запуске лаунчер проверяет маркер готовности, точку входа и файлы,
перечисленные в манифесте. Если файл отсутствует, скачивается только его
артефакт. После проверки загрузки лаунчер восстанавливает недостающие файлы
в существующем каталоге. Для этого файловая система кэша должна поддерживать
жёсткие ссылки. Исправные файлы остаются доступны другим сессиям.
На Unix лаунчер также восстанавливает утраченное право владельца на запуск ядра после сверки SHA-256 с манифестом. Для движков в кэше он также проверяет содержимое перед восстановлением права на запуск. При ошибке запуска мост передаёт в журнал DSH последние сообщения процесса.

**Релей ответов.** Лаунчер не отдаёт stdio сервера напрямую: он построчно читает
`tools/call`-ответы и, если успешный ответ пришёл с пустым `content` и полезной
нагрузкой только в `structuredContent`, подставляет её одним текстовым блоком.
Иначе DSH — он проецирует модели только `content` — показывает
`(unica.view returned no model-visible content)` и не пускает в кадр ни
`executionToken`, ни `can`-словарь узла, ни `next`-подсказки, ни `taskId`. Ответы с собственным текстом передаются без преобразования. Поле `structuredContent` сохраняется.

| Переменная | Смысл |
|---|---|
| `UNICA_BRIDGE_TEXT_FALLBACK=0` | отключить релей, вернуть сырой stdio |
| `UNICA_WORKSPACE_ROOT=<путь>` | лаунчер: закрепить каталог при ручном запуске (мост его не использует) |
| `UNICA_ARTIFACT_DELIVERY=background\|eager\|off` | докачка движков в фоне (по умолчанию), до старта или никогда. Явный `artifactDelivery` в настройках моста имеет приоритет |
| `UNICA_LAUNCH_SELFTEST_COMMAND=<json argv>` | тестовый хук: подменить рантайм |

В режиме `eager` сервер запускается после успешной доставки всех движков. Если доставить движок не удалось, запуск завершается с его именем и причиной ошибки.

По умолчанию лаунчер запускает ядро и в фоне скачивает отсутствующие в кэше
движки в порядке `v8-runner`, затем `bsl-analyzer`. После временной сетевой ошибки лаунчер выполняет до двух повторов. Если доставить движок не удалось, в журнале DSH указываются имя движка и причина. Если инструмент
сообщил, что нужный движок ещё недоступен, дождитесь строки
`unica launcher: <engine> delivered` в журнале сервера и повторите вызов.

### Структура

```
dsh-unica-plugin/
  install.mjs            установщик: профили, патчи, самопроверка
  host/                  нативный мост: пул процессов, имена, рендер, selftest
  bootstrap/launch.mjs   лаунчер: скачивает и запускает unica
  runtime-manifest.json  дескрипторы рантайма на три цели
  tool-map.json          11 инструментов: raw -> публичное имя DSH
  skills/                50 навыков unica-*
  references/            46 справочников
  tools/                 генератор навыков и проверки
examples/price-extension/     учебный проект 1С и запросы Unica
examples/verify-price-extension.mjs  проверка урока на временной копии
ci/                      проверка минимальной версии DSH и обновления из релиза
install.sh / install.ps1 установка одной командой
.github/workflows/       задания GitHub Actions
```

## Проверки

Из корня репозитория с Node.js 24 или новее:

```sh
node examples/verify-price-extension.mjs
```

Эту команду запускает задание `price-extension` на Ubuntu и Windows. На временной
копии проекта оно находит объявление и вызов BSL-функции, сверяет исходник формы
после предпросмотра, применяет правку по токену и запускает валидаторы `form`
и `cfe`. Для такой проверки достаточно ядра Unica. Чтобы дополнительно собрать
файл расширения и сверить его SHA-256, запустите ту же команду с `--build` на
машине с `v8-runner` и платформой 1С с `ibcmd`.

Проверки самого плагина:

```sh
cd dsh-unica-plugin
node tools/check-refs.mjs .       # ссылки навыков на справочники
node tools/check-encoding.mjs skills references
node tools/check-tool-names.mjs   # все имена инструментов резолвятся
node tools/build-runtime-manifest.mjs --check   # манифест артефактов не отстал от лока
node tools/verify-bridge.mjs      # лаунчер: релей ответов и защита доставки
node tools/ci-dryrun.mjs          # эмуляция CI-прогонов
node host/selftest.js --cwd .     # сквозная проверка моста без DSH
```

Как проверять живой режим в DSH (две сессии, две кодовые базы) — см.
[инструкцию проверки](docs/native-verification.md).

В CI задание `minimum-dsh` устанавливает DSH `0.2.2-rc.1`, создаёт агента и
вызывает зарегистрированный `unica.view` через нативный исполнитель DSH.
Тестовый MCP-сервер возвращает фактический каталог процесса. Проверка сверяет
его с рабочим каталогом сессии. Для локального запуска укажите каталог установки
npm в `DSH_INSTALL_ROOT` и выполните `node ci/minimum-dsh.mjs` из корня репозитория.

### Проверка обновления и отката

В PR установщика GitHub Actions устанавливает опубликованный релиз с пометкой **Latest**. Затем установщик из PR получает архив, собранный из той же рабочей копии и доступный по HTTP внутри раннера. Если версия в PR совпадает с опубликованной, проверка присваивает временной копии пакета следующий номер ревизии.

На Ubuntu и Windows тест добавляет пользовательские настройки в профиль и прерывает самопроверку обновления. После отката он сверяет исходные файлы и профиль побайтово и запускает восстановленный рантайм. Затем повторяет обновление и проверяет установленную сборку и настройки пользователя.

Вручную этот же сценарий запускается командой `gh workflow run published-upgrade.yml --ref main`. Для сравнения двух опубликованных релизов укажите в том же workflow `from_tag` и `to_tag`. Оба архива в этом режиме скачиваются из GitHub Releases.

При сборке релизного архива упаковщик проверяет обязательные файлы плагина. Если отсутствует модуль доставки движков `bootstrap/artifact-delivery.mjs`, сборка завершается ошибкой до создания архива и файла SHA-256.

## Обновление порта на новый апстрим

1. Прочитать changelog апстрима и **проверить, что он публикует архивы рантайма**
   под `darwin-arm64`, `linux-x64`, `win-x64` — без них порт не соберётся.
2. Склонировать апстрим и посмотреть, что стало с навыками и справочниками.
3. Обновить `runtime-manifest.json` из релизных дескрипторов.
4. Пересчитать `tool-map.json` по живому `tools/list` (формула выше).
   Сравнить входные схемы двух рантаймов командой
   `node ci/compare-tool-schemas.mjs /path/to/old/dsh-unica-plugin /path/to/new/dsh-unica-plugin`.
   Каждый каталог должен содержать лаунчер и манифест соответствующей версии.
   В JSON-отчёте перечислены добавленные и удалённые инструменты и изменения
   схем, включая обязательные аргументы. По отчёту проверить затронутые навыки
   и на новом рантайме пройти поиск BSL и изменение формы через `executionToken`
   в примере «Калькулятор цены».
5. `UNICA_UPSTREAM_PLUGIN=<путь> node tools/build-skills.mjs` — перегенерировать
   навыки; генератор упадёт, если появятся неизвестные имена инструментов.
6. Перечитать правила в персоне (`install.mjs`) — они описывают контракт
   инструментов и устаревают вместе с ним.
7. Прогнать `--verify` и проверки, пересобрать архив, выпустить релиз.

## Перенос на другую машину

```sh
curl -fsSL https://raw.githubusercontent.com/malinovme/dsh-unica/main/install.sh | sh
```

Либо скопировать каталог и поставить из него: `node install.mjs --target both
--verify`. Абсолютные пути в файлах плагина не хранятся.

## Удаление

```sh
rm -rf ~/.local/share/unica-plugin        # macOS / Linux
rm -rf "${DSH_HOME:-$HOME/.dsh}/unica"  # кэш рантайма и состояние демона
```

и удалить строки порта из `cordis.patch.yml` нужного профиля: `preset-unica-1c`
в пресетном, `unica-native` и `skill-filesystem-unica` — в остальных.

## Известные ограничения

- Для сборки `.cfe` нужны платформа 1С, доступная лицензия и `v8-runner`. Поиск BSL и проверка форм работают без платформы.
- На macOS рантайм доступен для arm64.

- **Пресет не виден в списке** — почти всегда значит, что мост не поднялся.
  Запустите `node install.mjs --verify`: он назовёт причину, а при отказе каталога
  перенесёт кэш сам.
